# 内层固定点加速：方法与实测结果

## 为什么选这里

作者的求解器在每次外层投影次梯度更新后，反复执行功率固定点更新 `p_new[k] = SINR_target[k] * p[k] / SINR[k]`，直到变化量足够小。困难样本的内层轮数较多。我们采用已有的 [Anderson 固定点加速方法](https://epubs.siam.org/doi/10.1137/10078356X)：结合近期的迭代及残差，估计下一次功率向量。目标是减少**内层迭代和总求解时间**；这与前一项“相同矩阵方程复用”计算优化不同。

`anderson_problem.py` 以 `OptimizedProblem` 为基础；通信模型、AP 功率/SINR 约束、外层步长 `kappa/sqrt(t)`、外层停止与不可行判定不变。第一次外层迭代仍执行作者的普通固定点更新，以保留总功率不可行性初筛。之后最多利用最近 3 个残差，按最小二乘得到候选，使用 0.8 阻尼。

保护规则：候选必须有限且逐项为正；组合系数绝对值不超过 2；与作者普通更新的距离不超过当前残差范数的 2 倍；预测残差范数至少下降 20%。不通过时使用作者更新。如果下一轮实际残差变大超过 50%，清空历史。内层停止时除作者的总功率变化阈值外，还检查完整功率向量的固定点残差，以免加速混合造成“总和碰巧不变”的假收敛。这些保护是本项目的工程设计，不是对该非线性无线模型的收敛定理。

## 开发与独立验证

开发时只查看种子 4、18、26。种子 18 内层轮数 256→173、种子 26 为 609→401；两版均满足作者的成功判定。种子 4 的内层轮数 440→401，但两版在 120 次外层上限内均未收敛。开发原始数据和日志保存在 `results/anderson_development/`。

规则固定后，测试了此前未查看的种子 **46–75**，共 30 对。采用论文 Figure 3 的网络维度：16 AP、16 UE、每 AP 4 天线、簇大小 4、100 次信道实现、1000 m 区域、3.5 bit/s/Hz、每 AP 1000 mW；两版同为 `kappa=17`、内层容差 `1e-5`、外层容差 `0.1 mW`、最多 120 次外层迭代。每个种子重新构造同一随机场景，按奇偶交替运行先后。

| 指标 | 现有缓存版 | 增加 Anderson |
| --- | ---: | ---: |
| 作者规则判定成功 | 15/30 | 15/30 |
| AP 功率差 ≤ 0.1 mW 且对偶差绝对值 ≤ 0.1 mW | 15/30 | 15/30 |
| 合计内层迭代 | 3880 | **3019**（减少 22.2%） |
| 合计外层迭代 | 523 | 520 |
| 合计求解时间 | 24.60 秒 | **19.41 秒**（减少 21.1%） |
| 达到外层迭代上限 | 2 | 2 |
| 程序错误 | 0 | 0 |

双方均成功的 15 个场景中，Anderson 有 9 个减少内层迭代、6 个相同、0 个增加；成功状态和更严格的功率/对偶差判定在全部 30 对中一致。成功样本的最终最大 SINR 缺口（作者输出四位小数）两版均不超过 `0.0001`；Anderson 的最大 AP 功率超限为 `0.00595 mW`，最大对偶差绝对值为 `0.09552 mW`。双方均成功的样本中，最终最大 AP 功率差的两版差异不超过 `0.01612 mW`，最终对偶差的两版差异不超过 `0.00469 mW`。数值轨迹可能略有不同，但保持所设容差内的判定一致。

另选非平凡场景 51、72、75 各重复 3 次，交替先后顺序。每个场景的加速比中位数分别为 `1.1752`、`1.4605`、`1.2475`；三个中位数再取中位数为 **1.2475 倍**。这是相对已加速缓存版的增益，不能直接与此前相对原版的 `8.90 倍`相乘作为新测量结论。

完整逐轮日志、随机种子、每 AP 功率、耗时和图在 `results/anderson_new_seeds/`；重复计时在 `results/anderson_repeats/`。运行命令：

```sh
export OPENBLAS_NUM_THREADS=1 MPLBACKEND=Agg MPLCONFIGDIR=/tmp
python3 experiments/benchmark_anderson.py
python3 experiments/analyze_anderson.py results/anderson_new_seeds
python3 experiments/benchmark_anderson_repeats.py
```

结论仅适用于这些网络样本、容差和计算环境。它改进的是**内层求解收敛效率**，没有证据表明提高了系统通信速率或可行率，也没有证明所有网络都必然加速。
